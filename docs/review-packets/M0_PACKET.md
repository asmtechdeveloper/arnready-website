## 4. Deviations from the manual

1. **Feather icons hand-rolled instead of an npm package.** The design
   system calls for "Feather icons through `src/components/Icon.tsx`".
   Installing the `react-feather` package would be a new npm dependency,
   which manual §0.10 lists as a stop condition. Instead,
   `src/components/Icon.tsx` inlines the handful of Feather-project SVG
   path outlines (ISC-licensed) needed so far. No new dependency was added
   for this.
2. **Homepage (`/`) was built, though M0's step 5 only lists the eight
   compliance/standard pages.** The header logo links to `/` and Next.js
   requires a root `page.tsx` for the route to resolve at all, so a lean
   WORKING homepage (hero + 3-step + honesty block, from copy scaffold §2)
   was added to keep the scaffold navigable. This is intentionally minimal
   — the manual reserves the full "four pillars" homepage build for M6.
3. **`npm run build` cannot be exercised end-to-end in this session** — see
   §5, Known limitations. `prebuild`/`postbuild` are wired exactly as
   specified; `next build` (the static-export step) and the leak gate were
   each verified directly.
4. **Vitest pinned to `3.2.7`, not the `3.2.4` originally installed** — a
   patch bump made mid-session after `npm audit` flagged a critical
   vulnerability (GHSA-5xrq-8626-4rwp, arbitrary file read via the Vitest
   UI server) fixed in `3.2.6+`. Same dependency, no version range change,
   done to close a critical CVE before the first commit.

No other deviations.

## 5. Known limitations / deferred

- **No Firestore service-account key is available in this execution
  environment** (by design — `.env.example` and `scripts/export-content.mjs`
  both require Anusha's local credentials, never committed). This means
  `npm run build` (which runs `prebuild` → `export-content.mjs` →
  `check-paid-leak.mjs` → `next build` → `postbuild` →
  `check-paid-leak.mjs` again) cannot be run end-to-end here — it fails at
  the `export-content` step with a clear "missing key" error, which is the
  script's intended fail-closed behaviour, not a defect. It has not been
  run successfully against live Firestore data by this session; that
  requires Anusha's machine. M0 introduces no Firestore-backed pages
  (chapters/subtopics land in M1), so this doesn't block M0's own
  acceptance — the static export itself (`next build`) and the leak gate
  itself were each verified directly, and the leak gate additionally has
  five passing subprocess-integration tests (`test/check-paid-leak.test.ts`)
  covering fail-closed, structural, id-leak, text-leak, and clean-pass
  scenarios without needing real Firestore data.
- **`npm audit` reports 8 moderate-severity vulnerabilities**, all
  transitive and build-time-only: (a) a `postcss < 8.5.10` XSS advisory
  nested inside `next`'s own bundled copy of `postcss` (the top-level
  `postcss` dependency pinned in `package.json` is `8.5.19`, unaffected);
  (b) a `uuid` bounds-check advisory nested several levels inside
  `firebase-admin`'s `@google-cloud/storage` → `teeny-request`/`gaxios`
  chain, exposed only to `scripts/export-content.mjs`'s local, trusted
  build-time execution, never to a browser or end user. Fixing either
  requires a major downgrade of `next` or `firebase-admin` respectively —
  out of scope for a scaffold milestone; flagging for Anusha's awareness
  rather than silently accepting.
- All new page copy is marked WORKING per manual §0.8 and still needs
  Anusha's voice pass plus the E-1/E-2 review prompts (scheduled for M6).
  Several facts carry explicit `[VERIFY]` markers (exam format numbers) or
  `[SLOT]`/`[ANUSHA-DECIDE]` markers (About page origin story, iOS
  timeline) rather than being invented.
- Chapter weightages on `/syllabus` are presented as an ordered study path
  only, explicitly marked `[VERIFY]` — no per-chapter mark split is stated,
  since that data isn't available yet and inventing it would violate the
  copy rules.
- No `/chapters` routes, `/app/*` routes, or question rendering exist yet —
  correctly out of scope for M0 (M1/M2/M3 territory).
